## 1. 门禁（先于一切跑批；每项均有自动测试）

**G1 真实补丁完整性门禁**（对 real 与 partial 的源 diff）：
- diff 必须覆盖 vuln→fixed 的**全部**变更文件（新增/删除/重命名/修改）；
- 禁止按字典序截取文件子集；禁止从 hunk 中间截断；
- 若完整 diff 超预算：**预注册**"语义完整的最小修复"（逐 CVE 写清裁剪规则
  并保证安全机制完整）或**排除该 CVE**——二选一，不允许静默截断；
- 自动断言：注入的 real diff 含该 CVE 安全关键 hunk（对 15 子集，与
  partial_arm_construction.md 的 hunk 表对齐）。

**G2 placebo 可应用与匹配门禁**：
- placebo 在真实 vuln 文件上以真实行号构造（语义保持重构或与漏洞无关的
  生产代码变更），`git apply --check` 对每个 CVE 必须通过；
- 文件数、hunk 数、总长度与 real diff 匹配（长度比 ∈ [0.5, 2.0]）；
- 禁止任何自述性标记与教学性提示（v3 已修，v4 保留）。

**G3 全输入落盘门禁**：逐调用保存——system+user prompt 全文、注入 diff 全文、
CPG 切片、prompt/diff 的 SHA-256、模型名与 digest、Ollama/HTTP 元数据、
seed/温度/max_tokens、时间戳、运行环境 manifest（硬件/OS/版本）。

**G4 统计口径门禁**：paired_metrics 实现 **strict 主路径**（--rule strict|lenient，
默认 strict；lenient 仅供历史对照并显式标注）；文档引用脚本须过
`verify_claims.py`（新增：扫描文档中引用的脚本路径是否真实存在 +
抽查表内数字能否由入库脚本复算）。

## 2. P1-13 protocol deviation 申报（补记，非新承诺）

- **D1 弃权阈值**：预注册"单轮 abstain>20% 作废重跑"，实际两轮 48%/45% 仍保留；
  事后解释为"阈值仅针对网络故障"（故障率 3.2%）。**这是 deviation**：原规则
  未区分故障类型。处置：保留结果，双口径申报（按原规则的作废后果 vs 按
  故障子集的有效结论），后续轮次执行修正规则。
- **D2 分支定义重叠**：预注册 A 含"McNemar 不显著"析取项，与 C 的"6-9/82"
  区间重叠——7/82 + p=0.0625 同时满足 A 字面与 C 区间。处置：判读采用
  "C（方向偏 B 但不显著）"，A/C 重叠作为协议缺陷申报；后续协议分支必须互斥。
- **D3 分母措辞**："双端非 abstain 的完整对上判别统计"字面=受限分母，
  执行为分母保留 82、弃权对不贡献判别事件（更保守），已勘误留痕。
