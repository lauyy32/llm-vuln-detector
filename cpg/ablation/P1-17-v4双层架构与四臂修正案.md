## 0. 本轮修正的动因（外部验收，全部核实属实）

1. **概念混淆（我方错误）**：前轮汇报把 "partial/minimal-real" 当**同一个**第四臂表述。
   二者构造目的与 ground truth **相反**，必须分开。
2. **表示层静默删证据**：`excerpt_vuln_for_patch` 的内部字符预算会整体丢弃触及文件，
   实测 `FULL=146 / PARTIAL=0 / ABSENT=138`（73498 = 15 FULL / 75 ABSENT）。
3. **长度匹配未解决**：按最终 prompt token 复算，placebo 14/15、shuffled 11/15 超出
   `[0.8, 1.25]` —— Gate A 的失败**不只是** 4 例上下文越界。
4. **请求 envelope 未冻结**：当前对所有臂把 `SYSTEM_V4` 拼进 prompt 本文；若调用时
   再经 Ollama `system=` 传一次会重复注入。

## 1. 臂的定义（概念澄清，禁止再合并表述）

| 层 | 臂 | 构造 | ground truth |
|---|---|---|---|
| **描述性** | `full-real` | 上游 fix-commit 的完整 Python 投影 | benign（仅报告可表示性与模型表现，**不**作因果推断） |
| **确认性** | `minimal-real` | security-complete 最小真实修复（机械 ddmin + 独立验证） | **benign** |
| **确认性** | `partial` | 从**同一 minimal-real** 机械移除预先标注的安全关键 hunk | **vulnerable** |
| **确认性** | `placebo` | 同文件、AST/行为中性、**按最终 prompt token 匹配** | **vulnerable** |
| **确认性** | `shuffled` | donor ≠ 目标；**约束匹配（token 匹配）**，非循环取下一个 | **vulnerable** |

- **禁止**写 "partial/minimal-real 第四臂"。
- 确认性四臂 = `minimal-real / partial / placebo / shuffled`（**4 臂**）。
- 描述性层（`full-real`）与确认性层**分母必须分开报告**：
  - 确认性：eligible 数 × 4；
  - 描述性：候选数 × 1（若同时报告四臂草案，则为 × 4 并标明 `DRAFT_TRIPLE_ARM`）。
- **不采用**"13 例 full-real + 1 例 minimal-real"的未分层混合设计。

## 3. 新增门禁：逐 hunk 覆盖（security-hunk coverage）

对每个候选样本、每个 real-patch hunk，报告其 **vulnerable 行范围**在表示中的覆盖：

```
FULL    / PARTIAL / ABSENT
```

**停止条件（硬）**：

| 情形 | 处置 |
|---|---|
| security-critical hunk 的 vulnerable 位置 = `ABSENT` | **不得进入确认性分析** |
| security-critical = `PARTIAL` | 仅可进敏感性分析，或经 reviewer 明确批准 |
| 普通非关键 hunk 被预算省略 | 允许，但**必须计数并落盘** |

- 仅 "code_text 非空" **不满足**本门禁。
- `security_critical` 标注须由协议/人工录入（`v4_hunk_coverage.json` 已留字段）。
- 现状：`ABSENT=138`（5 样本）→ 表示策略必须先修正，否则确认性样本会被大幅削减。

## 4. 长度匹配口径（替代 A4b 的"做不到则逐例报告"）

- **匹配对象 = 确认性 `minimal-real` 的最终 prompt token**（**不是** `full-real`）。
- 比值界 `[0.8, 1.25]`，用**未舍入**原始比值判定。
- `placebo`：按最终 prompt token 匹配（不是按补丁 token）。
- `shuffled`：donor 采用**约束匹配**（token 匹配），禁止简单循环取下一个 CVE。
- 匹配失败：**重新生成或预先排除**，二选一；不得带病入组。
