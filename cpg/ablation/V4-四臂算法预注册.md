## 一、冻结参数（机器可读副本见 `artifacts/v4/v4_prereg.json`）

| 参数 | 值 | 说明 |
|---|---|---|
| `window` | **20** 行 | 每个 hunk 的 vuln 侧前后上下文各 20 行 |
| `max_chars`（摘录预算） | **24000** | 按**稳定排序**累积，超预算的文件整体丢弃并计数 |
| `stable_sort_key` | `(file_path, old_start, old_count, new_start, new_count, body_lf_sha256)` | 文件与 hunk 的**确定性排序**，不依赖 dict/FS 顺序 |
| `critical_priority` | `SECURITY_CRITICAL` **优先纳入**，其后按 `stable_sort_key` | 预算不足时先保关键 hunk |
| `dependency_closure` | 对 `SECURITY_CRITICAL` 的 `dependency_group` 取**传递闭包**，闭包成员一并纳入 | 保证"联合必要"的 hunk 不被人为拆散 |
| `budget_relief` | 关键 hunk **不得**因预算被丢弃；非关键可丢弃并**计数落盘** | 防止"表示层删掉核心证据" |
| `unrepresentable_rule` | 若 critical hunk 仍无法纳入（预算/文件过大）→ 该样本 **`ABSENT`**，进 `confirmatory_blocking` | 不得静默降级 |
| `tie_break` | 同优先级下按 `stable_sort_key` **字典序最小者优先** | 确定性 |
| `role_mapping` | `DIRECT_SECURITY` / `SUPPORTING_REQUIRED` → `SECURITY_CRITICAL`；`NON_CRITICAL` → `NON_CRITICAL`；`UNCERTAIN` → 不得进入确认性（见 §三） | 唯一映射，无自由度 |
| `placebo_token_target` | 以 **minimal-real 的最终 prompt token** 为基准，比值界 `[0.8, 1.25]`（**未舍入**判定） | 非 patch token |
| `shuffled_donor_rule` | donor ≠ 目标；在**约束匹配**下选 token 最接近者（非循环取下一个） | 须报协变量平衡表 |
| `num_ctx` / `num_predict` | `32768` / `1024` | context-fit 判定：`prompt_tokens + num_predict <= num_ctx` |

## 二、minimal-real / partial 的构造（机械，无人工挑选）

```
输入：real patch 的 hunk 列表 + frozen registry 的角色标签 + 依赖图
1. 取 S = { h ≤ real hunks | role(h) ∈ {DIRECT_SECURITY, SUPPORTING_REQUIRED} }
2. 闭包 C = transitive_closure(S ∪ ⋃ dependency_group(S))
3. minimal-real = 保留 C 中全部 hunk（其余删除）
4. partial      = 从 minimal-real 中删除 S 里 role=DIRECT_SECURITY 的 hunk
                 （保留 SUPPORTING_REQUIRED，使 partial 呈"有防护设施但未接线"）
5. 验证：minimal-real apply-clean + oracle 显示漏洞已修复；
        partial apply-clean + oracle 显示漏洞重新出现
若 oracle 不成立 → **该样本排除**（记录原因），不进入确认性分析
```

**命名纪律**：若使用 oracle-driven 最小化，可称 `1-minimal security-complete patch`；
**不得**宣称"全局最小"，除非穷举所有子集。无可执行 oracle 时只能称
**reviewer-guided minimization**（证据等级降级）。

## 三、UNCERTAIN 与排除（预注册规则，不受结果影响）

| 情形 | 处置 |
|---|---|
| 双方一致且确定 | 直接采用 |
| 双方分歧 | 第三人仲裁（须填全 `final_*`） |
| 任一方 `UNCERTAIN` | 进入 `uncertainty_review` |
| 复审仍无法确定 | **整例（CVE）排除**，须结构化记录 `reason/adjudicator/evidence=insufficient/source_item_ids`，且 `source_item_ids` **必须等于该样本全部 pending hunk** |
| 排除后样本不足 n=8 | **主 estimand 降级为探索性**，claim 收窄为"外观敏感性" |

**红线**：不得因"结果不好看"而排除确定样本（`exclusions ⊆ pending_uncertain` 已在代码层强制）。

## 四、主 estimand 与统计口径（预注册）

- **主 estimand**：`pairwise sufficiency discrimination rate`
  —— real 判 benign **且** partial 判 vulnerable 才算正确区分。
- **主比较**：`minimal-real`（确认性 real）vs `partial`（配对）。
- **报告**：exact 95% CI + 三项分解（real-acceptance / partial-rejection / abstain）。
- **平凡基线**：配对平衡语料上"全判 vulnerable"的 F1 = 0.667 —— **凡报 F1 必须并列 BA/MCC 与该基线**。
- **功效**：功效分析显示 m=8 时 p1=0.90 的功效仅 0.43；检出 90% 效应需 **m=12** discordant pairs。
  → 若最终 m < 12，结论必须标注"判别力有限"（**不得**写 `underpowered` 作为结论性表述，
  功效不足只在引用功效分析时讨论）。
- **长度混淆**：报告 `patch_token_ratio` 与 `final_prompt_token_ratio` **两者**，
  并把 patch 长度作为**协变量**做敏感性检验（避免把长度线索误读为语义线索）。
