## 一、命名口径（**不宣称最小化**）

原命名 `minimal-real` / `partial` 与算法不符：前者实际保留全部 `DIRECT_SECURITY` +
`SUPPORTING_REQUIRED`（**并未执行最小化**），后者删除全部 `DIRECT_SECURITY`
（不是"只缺一个必要组件"的近邻）。**本版改名**：

| 旧名 | 新名（正式） | 定义 |
|---|---|---|
| `minimal-real` | **`annotated-security-complete`** | 保留 `closure(S ∪ deps(S))` 的全部 hunk，S = {role ∈ {DIRECT_SECURITY, SUPPORTING_REQUIRED}}；**标注意义上的安全完备**，不声称最小 |
| `partial` | **`support-only-insufficient`** | 从前者删除**全部** `DIRECT_SECURITY`，保留 `SUPPORTING_REQUIRED`（呈"有防护设施但未接线"） |

> 若将来要使用 `minimal-real` 之名，必须先预注册**确定性 oracle-driven minimization 算法**
> 及其**全部中间记录**（ddmin 序列、每步 oracle 结果），否则不得使用该名称。

### 3.1 placebo（**待定义**）

### 3.2 shuffled（**实现已落地**：`v4_arms.select_donor`，待评审确认后冻结）

```text
【候选 prompt 的语义（评审 5 纠正）】
  shuffled 臂的候选 prompt = **目标**源码上下文 + **donor** patch + **目标** envelope，
  因此**不等于** donor 自身 CVE 的 prompt。故不得用 donor 自身 prompt 做比对，
  须引入 **target×donor 级**工件 `PairCandidateArtifact`：
      target_id / donor_id / target_tree_sha256 / donor_patch_sha256 /
      post_apply_tree_sha256 / candidate_prompt_sha256 /
      candidate_final_prompt_tokens / tokenizer_sha256 / envelope_sha256
  长度门禁比较的是：
      「目标**基准臂**最终 prompt token」 vs 「target×donor **候选**最终 prompt token」

硬约束（不可放宽）：
  ① donor != 目标样本；
  ② apply-clean 须有**可复算的内容证据**：候选工件须提供 `post_apply_tree_dir`，
     由**实际 post-apply 目录**重算 LF 归一化递归 tree SHA 并与记录值比对；
     该 SHA 须与 target tree 不同（否则补丁未生效）；并须绑定**受控 apply runner**
     的执行记录（runner 实现 SHA / command / exit_code / stdout SHA），
     runner SHA 须等于 frozen_runtime.apply_runner_sha256。自报字段不足采信。
  ③ 长度门禁（见上）须落在 [0.8, 1.25]，由**权威 token 数重算**；
     tokenizer / envelope SHA 须等于 frozen_runtime。

软约束（**按逆序逐条放宽**，放宽序列完整落盘）：
  not_composite → same_file_count → same_cwe_family → same_language

无候选处置：全部软约束放宽后仍无候选 → `NO_DONOR` 并附逐候选拒绝理由；
            权威工件缺失 → `NO_AUTHORITY`（**不得**退化为 schema 检查）。

协变量平衡表字段：language / cwe_family / base_final_prompt_tokens /
                  candidate_final_prompt_tokens / n_files / is_composite
                  （target 与 donor **两侧**均报告）。

tie-break：|候选 token − 基准 token| 升序，同距按 sample_id 字典序。
```

### 3.3 oracle（**实现已落地**：T1/T2/T3 分层契约，待评审确认后冻结）

```text
【核心规则】verdict 的**唯一权威来源**是 oracle 原始输出中的显式标记行：
      VERDICT: fixed | still_vulnerable | ORACLE_ERROR
    （须位于行首，大小写不敏感；多个标记取值不一致 → ORACLE_ERROR）

【exit code 的角色】仅用于分类"本次运行是否有效"，**不参与**漏洞状态判定。
    废除旧的 exit → 漏洞状态 映射，理由：
      · pytest 退出码 1 只说明有测试失败（可能是断言错误/环境错误/无关回归）；
      · PoC 脚本退出码 0 只说明脚本正常结束，不等价于"漏洞仍存在"；
      · SAST 退出码跨工具语义不一致，不能统一解释。
    约定外的退出码、以及登记为 infra 的退出码 → 一律 ORACLE_ERROR。

【第三状态】无法判定（无标记、标记冲突、infra 失败、契约未登记）→ ORACLE_ERROR，
    **不得**压缩为 fixed / still_vulnerable 二分类。

【分级证据（三类分别报告，不混为同一证据等级）】
    T1 可执行 oracle：命令模板 + 工具版本 + valid/infra 退出码集合 + 必需标记
       + 对照样本（已知已修复/已知仍可利用）+ 故障注入用例；
       强制提供 PoC、patch、target tree 三个工件引用，并**重算**
       PoC SHA / patch SHA / LF 归一化递归 tree SHA。
       ⚠ `tool_version` / `command_template` / 对照样本 / 故障注入目前是**登记文本**，
       尚未由真实 runner 落盘核验；冻结时必须用实际工具版本与命令输出对齐后再启用。
    T2 确定性语义断言：同上，另须提供 **checker 文件路径**、重算其内容 SHA，
       并与冻结 arm 规格绑定（防「改断言迁就结果」）；强制 patch 与 target tree（PoC 非必需）。
    T3 无可执行/可脚本化 oracle：**machine_decidable = False**，由以下**真实工件**承载：
       冻结的书面残余利用路径（路径 + 重算 SHA）、
       **两份独立 reviewer submission 文件**（各提供路径 + 重算 SHA；不得同一文件、
       不得同一人）、两人**独立 verdict**；
       两人 verdict 分歧时必须提供**仲裁工件**（路径 + 重算 SHA）与仲裁结论，
       否则强制 ORACLE_ERROR（待仲裁）。
       T3 **同样执行**通用 provenance 检查（raw_result 重算、parser SHA、manifest 与
       template 绑定、sample/arm 存在性、书面材料重算），**不得**提前返回绕过。

【构造门禁与结果评估**彻底分离**（评审 5 裁定，本版采纳）】
  `construction_gate`（**运行前**）：决定样本/臂是否纳入 active universe。
    其签名中**不存在任何模型输出参数**，只消费 apply-clean、工件绑定、长度门禁
    与（该臂要求时）oracle 证据。
  `outcome_evaluation`（**运行后**）：记录模型判定与操纵检验结果，
    恒 `changes_inclusion = False`，**不得**改变 active universe / schedule / 分母。

【逐臂接受标准】
  annotated-security-complete : apply-clean 且 oracle 显示漏洞已修复      （要求 oracle）
  support-only-insufficient   : apply-clean 且 oracle 显示漏洞重新出现    （要求 oracle）
  placebo / shuffled          : **仅需 apply-clean**（不要求 oracle 复现）
    ⚠ **口径裁定（评审 5）**：原文「判为 vulnerable」**不是**构造接纳条件，而是
      **预期标签 / 运行后操纵检验**。模型判定是因变量，绝不可反过来决定样本有效性 ——
      否则会形成结果感知筛选（误判 benign 的样本被剔除、判 vulnerable 的保留），
      使统计天然偏向预期。因此 placebo / shuffled 的构造门禁**不得消费模型输出**。
    · 附加 oracle（若提供）只做**构造一致性**检查：证据必须可验证；若显示目标漏洞
      被意外修复 → 该臂非行为中性，属**构造失败**（与模型输出无关）。

失败处置：oracle 不成立 → 该样本排除并记录原因；**不得**据此反向挑选 hunk 子集
```

## 五、统计口径（修正两处，**必须可复算**）

### 5.1 平凡基线的适用范围（修正）

`F1 = 0.667` 是**平衡的 arm-level 二分类**下"全判 vulnerable"的平凡基线，
**只能作为次级参考**，**不得**与主 estimand（`pairwise sufficiency discrimination rate`）
直接比较——两者**样本单位不同**（arm-level vs 配对）。

- 主 estimand（配对判别率）：报告 exact 95% CI（Clopper–Pearson）+ 三分分解
  （real-acceptance / partial-rejection / abstain）。
- arm-level 指标（若报）：必须**并列** BA / MCC / F1 与 0.667 基线。

### 5.2 功效分析的完整参数（修正）

```
检验      : McNemar 精确检验（双侧）
α         : 0.05
零假设    : 配对判别率 p = 0.5（无判别能力）
目标功效   : 0.80
效应       : p1 = 0.90（判别成功比例）
样本单位   : **discordant pairs**（不是 arm、不是 CVE）
结论       : m = 8 时条件功效约 0.43；
             m = 12 是**首次跨越** 0.80 的点（在 p1=0.90、α=0.05 下）
```

**⚠ 措辞约束（评审 5，本版采纳）**：离散精确检验（McNemar exact）的功效**不随样本量
单调**（实测：m=11 的条件功效 0.6974 **低于** m=10 的 0.7361）。因此：

- `m = 12` 只能表述为**首次跨越点**，**不得**直接称为"所需最小 m"；
- 只有在明确核验窗口内**持续不跌破**目标功效时，才可使用"最低所需"措辞
  （工具：`v4_power.sustained_crossing_m` / `sustained_crossing_N`）。
- 非条件功效（与 N、discordance 相关）亦须逐参数组合表述；功效结论只能绑定
  **具体参数组合**（N / p1 / discordance 三者给出），**不得**对整张敏感性表作笼统判断。
  **实测限制**：在
  p1=0.90 且 q ∈ {0.3, 0.5, 0.7} 这**三个已列出的取值**下，首次跨越 N 为
  41 / 25 / 17，均超出计划窗口 N ≤ 14 → 该窗口内**不得**声明任何"最低所需 N"。
  **不得**把该结论外推为"任意 discordance 下都达不到 0.80"。

若最终 m < 12：结论标注"**判别力有限**"（**不得**把 `underpowered` 当作结论性表述；
功效不足仅在引用本节时讨论）。该判定**限定于本节参数** `p1 = 0.90`、`α = 0.05`、
目标功效 0.80；换用其它假设须用 `v4_power.power_report` 重算后再表述。
