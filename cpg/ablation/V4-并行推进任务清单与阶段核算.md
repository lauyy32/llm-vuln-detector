## 二、可并行推进的任务（A 类：不受标注结果影响）

### A-1 标注分发与登记（现在）
- **A-1.1 分发**：`标注交接说明.md` + `critical_hunks.reviewer{1,2}.jsonl` 分别私下发给两人（互不可见，不讨论）。
- **A-1.2 分发登记表**：固化并记录 SHA —— template / 交接说明 / 两份空白 reviewer 文件 / 生成器 git commit + 实现 SHA / canonical manifest SHA / real patches tree SHA。
  > 用途：日后证明"两人拿到的是同一协议同一版本"。
- **A-1.3 回收通道**：约定两人**私下单独**提交（先交者结果不得出现在后交者可见位置）。

### A-2 回收后流水线（现在可写，**不预填仲裁结果**）
- **A-2.1 一键只读流水线**：`validate_submission ×2 → agreement_report → disagreement_list`，输出 κ、各字段一致率、分歧清单。
- **A-2.2 仲裁空模板生成**：只生成 `final_*` 为 `null` 的待填件，**不预填任何建议标签**。
- **A-2.3 只读保证**：流水线在校验失败时**不得落盘任何产物**（本轮已为 `adjudicate` 实现原子写盘，回收流水线沿用）。

### A-3 四臂构造器**框架**（可搭骨架，**不得产正式工件**）
- **A-3.1** `minimal-real` / `partial` 构造器的 **schema + 依赖闭包算法** + 错误处理 + 合成 fixture 测试。
  - 依赖闭包：按 frozen registry 的 `dependency_group` 做传递闭包保留；
  - **严禁**在此阶段用真实标注推断标签或生成正式补丁。
- **A-3.2** placebo / shuffled 的 **token 匹配框架**（接口 + 匹配算法 + 失败路径），目标值待 minimal-real 冻结后填入。
- **A-3.3** oracle 接口与**独立审核流程文档**（上游 PoC > 可执行安全属性测试 > 项目测试+静态机械检查 > 双 reviewer 判定并降级证据等级）；**不得根据未来模型输出调规则**。

### A-4 运行基础设施（现在可准备）
- **A-4.1** 真实 tokenizer 与 **Ollama envelope 冻结**（`system` / `prompt` 字段、是否重复注入、请求 JSON 快照）。
- **A-4.2** 调度器 + 结果验证器（verdict 绑定原始响应）+ **RUN_LOCK 模板**。
- **A-4.3** 统计脚本（主 estimand = **pairwise sufficiency discrimination**；exact 95% CI；三分解指标 real-acceptance / partial-rejection / abstain）+ McNemar/power 工具。
- **A-4.4** 双干净目录确定性复算脚本（复用本轮做法：**Windows 风格路径 + 显式清场**）。

### A-5 RQ1-R 正式化（**已完成实验，可独立收尾**）
- **A-5.1** 正式结果报告：列联表 + 置信区间 + CPG 分层分析。
- **A-5.2** 脱敏发布副本（PII 检查，公开文件用 `lauyy32`）。
- **A-5.3** 与 V4 的衔接说明（RQ1-R 是"模型能否识别漏洞"；V4 是"能否判断补丁充分性"）。

### A-6 论文层（**骨架可先写，数值标 provisional**）
- **A-6.1** RQ 定稿、方法章（含 placebo 协议 + 度量口径与平凡基线问题）、
- **A-6.2** 威胁与效度（长度混淆 / **given-location 限定** / ground-truth localization 不得外推）、
- **A-6.3** 负结果表述模板（CPG 确定性锁死 + LLM underpowered 弱信号）、
- **A-6.4** 复现性章节骨架（SHA 链、双目录、数据可用性、双盲标注协议）。
