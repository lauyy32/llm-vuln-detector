> 目的（Codex 要求）：区分"当时模型实际收到什么输入"（实验有效性）与"第三方现在能否重建
> 相同输入"（工件可复现性）。针对 85(D1) 集里 17 例语料未 git 入库的样本。

## 一、数据流结论

1. `dataset_d1.jsonl` 的字段为 `cve_id/ghsa_id/repo_slug/fix_commit/cwes/severity/summary/
   language/files/label`——**无内嵌源码字段**，`files` 只引用 `corpus_pairs/...` 路径。
2. 模型运行时从**本地磁盘 `corpus_pairs/` 目录**读取源码（当时本地 17 例均存在）。
3. **关键**：`cpg/ablation/seeds/v10_d1_7b/raw_llm_responses.jsonl`（1.3 MB，**已 git 跟踪**）保存了
   每条记录的 `prompt`（完整输入代码节选）与 `raw_response`。**因此 17 例当时的实际输入已固化
   落盘，可复现。**

## 三、四类分类结果

- **A 类（raw prompt 有完整输入，实验有效）**：**14 例**。prompt 含代码节选，模型收到完整输入。
- **D 类（空/残缺输入，判定无效）**：**3 例**（53500/59224/70485）。其 prompt 为 268 字符模板，
  代码上下文为 `# CPG TAINT SLICE (no untrusted input reaches a modelled sink)`——fixed 目录为空
  → CPG 切片为空 → 模型无实质输入，判 `benign`。**这 3 例正是 D1 文档已披露的"fixed 空"样本，
  其判定无效，须排除或补语料后重跑。**

## 四、对"17 例不可复现"的准确修正

Codex/Hy4 此前的表述"17 例工件里根本没有输入"**说重了一格**。实测：

- **结果可复现**：`raw_llm_responses.jsonl`（已 git 跟踪）保存了 17 例的完整 prompt + response；
- **语料源未入库**：`corpus_pairs/` 17 例目录未 git 跟踪，第三方无法重新构建语料、无法复算
  "从语料生成 prompt"的完整链路；
- **3 例输入本身残缺**（53500/59224/70485，空切片，D 类），判定无效，须处理。

故准确状态：**14 例"实验有效、工件语料缺失"（可复现结果、不可重建语料）；3 例"输入残缺、判定
无效"（须排除或重跑）**。这与"85 个历史结果全部作废"相距甚远。

## 五、结论与下一步

1. 17 例的定性已从"不可复现"精确为"结果可复现、语料源缺失；其中 3 例输入残缺"；
2. 3 例 D 类（53500/59224/70485）须按 D1 文档的 (A) 补 vendor 或 (B) 排除处理（本就在待决清单）；
3. 14 例 A 类的结果可继承，无需重跑（语料源缺失仅影响"从语料重建"的完整链路，不影响已固化结果）；
4. 语料源入库或重建脚本仍须做（审稿人须能重建语料），但不再影响 14 例结果的有效性判定。
