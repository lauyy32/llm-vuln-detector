# 结构型 CWE 专项覆盖率评估（74 样本）

> 评估时间：2026-09-01（基于扩样本后 74 CVE 主消融，seeds/v8_74 与 v8_74_14b）
> 目的：确认结构型 CWE（CWE-059/200/400/444/639/862/863）的语料覆盖是否充分，
> 并量化本系统在结构型漏洞上的实际检测能力，界定适用边界。

  单类样本偏少（≤8）意味着逐 CWE 指标置信区间宽，但足以支撑"是否存在检测能力"的定性判断。

## 3. 14B 改善边界

| 指标 | 7B | 14B | 变化 |
| --- | --- | --- | --- |
| 结构型 LLM F1 | 0.207 | **0.250** | +0.043 |
| CWE-863 LLM F1 | 0.00 | **0.67** | 突破（判对 CVE-2026-54707） |
| CWE-400/444/639/862 | 全盲 | **仍全盲** | 无改善 |

- 14B 仅突破 CWE-863（授权逻辑），其余纯逻辑/状态类（400/444/639/862）**即使 14B 仍全盲**。
- 结论：**模型规模无法弥补纯逻辑/状态类漏洞的检测缺口**——这不是参数规模问题，
  而是本框架的证据基础（污点/数据流切片）对这些漏洞无信号。

## 4. 结论与立论意义

1. **语料覆盖充分**：结构型 7 类全覆盖，专项覆盖率评估完成；后续无需为"覆盖"补样本，
   但单类样本量偏小，逐 CWE 结论宜作定性而非定量。
2. **能力边界明确**：系统适用域为**污点/数据流型漏洞**；对纯逻辑/状态型漏洞
   （DoS、请求走私、IDOR、缺失授权）系统性无效，应在论文中显式声明 scope。
3. **与现有立论自洽**：B-2 证据降级基准已证明 LLM 在"证据降级"时靠源码语义补全；
   但结构型全盲表明语义补全的边界同样在"可控状态/数据流可溯"之内——
   无数据流可溯的纯逻辑漏洞，任何"静态分析 + LLM"组合在本框架下均无效，
   这是未来工作的明确缺口（需运行时/多文件上下文或专用逻辑型基线）。

## 5. 对后续工作的启示

- 不将结构型 CWE 的零召回作为系统缺陷，而作为**适用边界声明**写入论文贡献与局限。
- 若需回应"逻辑类漏洞无效"质疑，可指出：本框架定位为数据流漏洞的增强检测器，
  逻辑类由专门的逻辑型分析器（不在本工作范围）负责，二者互补。
- 112 候选池中仍有部分结构型样本，提取时优先纳入 CWE-400/444/639/862 以增厚单类样本，
  但检测能力预期仍受证据基础限制，不应作为提升 F1 的主要杠杆。
