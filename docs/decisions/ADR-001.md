# ADR-001: 采用 CPG 代码级上下文作为课题核心创新路线

- 状态：Accepted（2026-08-07，基于 2026-07-28 与导师问答后的共识）
- 决策人：lauyy32

## 背景

1. **请求侧分析上限已现**：真实世界数据集三模式评测中，No-Context（F1 99.1%）反而略优于 CoT（F1 98.2%），请求侧"上下文增强"未显示稳定增益。模型名统一为 DeepSeek v4-pro 后重跑，结论不变。
2. **导师 2026-07-28 提出三个问题**，问题三直指 CPG：别人是否做过、LLM 能否看懂、是否只需数据不要图、相比 HTTP 请求的优势。
3. **课题全称**为"基于大语言模型的上下文增强智能漏洞检测"，"上下文增强"天然指向代码级上下文（CPG），而非仅 HTTP 请求上下文。

## 决策

课题下一阶段以 CPG（AST/CFG/DFG 提取 + 文本化切片）喂给 LLM 为主路线，设计「仅请求 / 仅代码(CPG) / 请求+代码」三模式消融，并与 CodeQL 基线在同数据集上正面对比。

## 后果

正面：

- 贴合课题名，跳出"请求分类器"被反复质疑的框；
- 上下文增益可被量化（三模式消融直接给出增量）；
- 与 CodeQL 对比可回答导师"相比已有方案优势在哪"。

负面 / 风险：

- 工程量大于请求侧（Joern/CodeQL 管线、真实 CVE 数据清洗）；
- 必须用真实 CVE 修复前后代码（Devign 真实仓库），用 SARD 类合成集会掉回"标准集 100%"模板化陷阱；
- LLM+CPG 未必优于纯 CodeQL，需诚实呈现两种结果。
